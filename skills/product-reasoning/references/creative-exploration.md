# Creative Exploration

Use when the obvious solution is weak, the current pattern feels stale, or the user explicitly wants exploration.

Creativity means **new + useful**.

Use:

`prepare → diverge → reframe → converge → verify`

## Prepare

Load the user outcome, current flow, evidence, constraints, existing patterns, failed attempts, and non-negotiables.

Ideas do not come from nothing. Weak inputs produce weak outputs.

## Diverge — flea moves

Jump away from the current solution space:

- What if we did the opposite?
- What if this surface did less?
- What if the user never had to make this decision?
- What if the system acted first and the user corrected it?
- What if we removed the assumed “main” feature?
- What assumption are we treating as a rule?
- What would the intentionally terrible version do?

Do not judge the first pass too early.

## Reframe — see the box

Change the question before changing the answer.

Instead of “How do we make users complete this form?” ask “Why does this need to behave like a form?”

Instead of “How do we make this faster?” ask “What if the product did less here?”

## Bad-idea inversion

1. Generate a deliberately bad idea.
2. State why it is bad.
3. Identify the dimension it exaggerates.
4. Flip that dimension into a useful move.

Bad ideas lower attachment to the current framing and reveal assumptions.

## Converge — ant moves

Make the promising direction useful:

- simplify;
- fit real constraints;
- remove novelty that does not serve the outcome;
- combine compatible ideas;
- identify the smallest testable form.

The flea provides surprise. The ant makes it work.

## Verification

Excitement is not evidence. Ask:

- Does it solve the actual problem?
- Is it understandable?
- Is the novelty useful enough to justify itself?
- What trade-off did it introduce?
- Can it be tested cheaply?

## Incubation for agents

Do not pretend to wait or think in the background. Approximate incubation with a deliberate second pass at a different abstraction level or perspective, then compare.

Useful switches: user ↔ system, screen ↔ timeline, feature ↔ underlying job, happy path ↔ interruption, current pattern ↔ opposite pattern.

Show the user only the strongest materially different directions, not raw idea spam.
