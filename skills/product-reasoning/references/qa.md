# Product QA

Before declaring a meaningful product change done, check four axes.

## Outcome

Did the implementation improve the intended user outcome, or did it drift into solving a different problem?

## Decision

Does the user know what is being asked, why it matters, and what happens next? Is unnecessary choice removed while meaningful choice remains?

## Timeline

Where relevant: is feedback immediate enough, waiting understandable, success truthful, failure recoverable, and return/resume coherent?

## Constraints

- Human: understandable and usable?
- Business: supports the intended outcome?
- Technology: reliable and maintainable?
- Risk: trustworthy and safe enough for the consequence?

Final test:

> Could this pass code review and still confuse the user?

If yes, the product work is not done.
